CASE 自主排查

从硬编码 SOP 到证据驱动排查 · 知识驱动假设形成 · 排查经验持续积累

旧模式 硬编码 SOP
排查步骤写在 skill 文件里，新类型必须改 skill
路径固定，机械走完步骤 1→2→3，无法提前收敛
每次排查从零开始，经验无处积累
→
新模式 证据驱动排查
skill 只定义执行框架，业务知识全部在知识库
假设集驱动，证据足够时提前收敛，发现新线索时动态插入
Phase 5 自动沉淀，线索层逐步精化

🎯 线索层
核心
线索层 — 假设驱动的推理框架
统一结构：触发信号 / 支持证据 / 否定证据 / 验证动作，给 Agent「触发→验证→排除」完整推理框架，而不是执行清单。
📂 案例层
案例层 — 真实排查过程记录
真实排查记录，保留边界条件和踩坑细节。线索层是通用规则，案例层补充无法泛化的细节。
🗄️ SQL
参考库
SQL 参考库 — 带陷阱注释的查询模板
带陷阱注释的查询模板，由线索层验证动作按需引用。
🔩 原子层
原子层 — 客观事实描述
客观事实描述，三个子目录：
表结构参考 指标计算口径 字段速查（含查询陷阱）
Phase 5 · 知识反馈闭环

📌 案例层可自动写入；线索层修改必须人工确认。
❌错误路线
追问正确根因，对错误命中的假设逐一归因
归因类型：触发信号过宽 / 执行判断失误 / 线索层缺失
