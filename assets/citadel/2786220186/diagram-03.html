上下文工程 长程任务 对抗上下文稀释

问题表现 — 约束仍在上下文中，但 Agent 的注意力被累积的对话历史和工具输出稀释，重要信息文件逐渐淡出视野。又或是长程任务触发多轮 Compact，早期加载的全局文件 / skills 保留不完整，语义缺失。

解法 — 通过 webhook / hook / plugin 等方式在用户消息输入时，注入 HINT-NOTE，使得 Agent 持续关注关键信息。

下图示例中，假设我们希望 Agent 持续关注的信息是 <全局信息> 和 <Skills> 这两部分的内容。

上下文利用度 弱 → 强
会话初期
System Prompt + Tools 全局信息 Skills 工具调用 消息 <ANCHOR>
Anchor 注入但无需发挥作用 — 上下文较为简短干净
多轮交互后
System Prompt + Tools 全局信息 早期对话 <ANCHOR> 工具输出 Skills 近期对话
↑ ↑ Lost in the Middle — 全局信息 / Skills 被淹没在冗长上下文中
多轮交互后 + 消息输入
HINT 提醒 → Agent 重新关注到关键信息
System Prompt + Tools 全局信息 早期对话 <ANCHOR> 工具输出 Skills 近期对话 消息 <ANCHOR>
Anchor 随消息注入 — Agent 找回关注力
✓ ANCHOR 是 HINT（引子）
「执行过程中严格遵守 xxx skill」
只点名关键信息，不含具体规则与约束细节；Agent 借由它重新读取文件、或在上下文中找回完整内容
vs
✗ 不是信息录入处
不把 skill 的约束条款、执行规则誊写进 Anchor
堆入细节会让 Anchor 膨胀，重新稀释注意力，也违背极简引子的设计初衷
