# 证据整理工作流

## 1. 先固定问题，不先堆资料

在检索前写清：研究问题、目标读者、时间和版本边界、用户指定的主来源、允许补充的来源、输出语言与截止条件。资料很多时按研究问题筛选，不按“搜到什么就写什么”组织正文。

若用户给出具体文档、版本或本地快照，它们是主输入。补充资料只能承担三种角色：解释背景、交叉核对、展示冲突。不得用较新的外部资料悄悄替换用户要求的历史版本。

## 2. 来源准入

每个来源进入写作前登记：

- `source_id`、标题、作者或发布方、来源类型；
- URL、本地绝对路径、content ID 或其他稳定定位；
- 发布日期、版本、提交号或“版本未知”；
- 访问日期和实际读取深度；
- 能证明什么、不能证明什么；
- 访问限制、截断、权限、动态内容或版本漂移。

读取深度只用：

- `full`：已读取与本任务相关的完整正文；
- `partial`：只读取了明确记录范围的部分正文；
- `metadata_only`：只有标题、摘要、目录或元信息；
- `unreadable`：内容不存在、受限、损坏或无法获取。

`metadata_only` 和 `unreadable` 只能证明其自身元信息或访问状态，不能支撑正文能力、效果或因果结论。搜索结果摘要用于发现来源，不作为最终证据。

## 3. Claim 分类

每个关键判断选择一个种类，不混写：

| kind | 含义 | 最小支撑 |
|---|---|---|
| `source_statement` | 可读来源明确说明 | 至少一个 `full` 或 `partial` 来源及页码、章节、行号或锚点 |
| `experiment_observation` | 本次运行直接观察 | 日志、代码位置、截图、数据文件或可复现步骤 |
| `inference` | 对多个事实的综合推导 | 可追溯来源或观察，并说明推导和适用范围 |
| `hypothesis` | 尚待检验的解释或方案 | 可证伪的验证方法和成功/停止条件 |
| `insufficient_evidence` | 当前不能建立结论 | 明确缺失证据和最小补证动作 |

“来源报告值”仍属于 `source_statement`，必须写明是谁、在哪个样本或配置下报告；未独立复现就直说。不要把单次 smoke、设计阈值或开发集结果改写成普遍效果。

## 4. 从台账到正文

1. 去重：同一原始来源的镜像、转载和摘要合并为一条来源链。
2. 分组：按研究问题或 Claim 聚类，而不是按资料文件顺序复述。
3. 对齐：比较对象必须使用相同维度；版本、任务、权限或指标不同则列为不可直接比较。
4. 处理冲突：并列来源、时间、口径和适用范围；证据不足时不强行裁决。
5. 写作：先写直接证据，再写推断；关键数字和结论使用邻近引用或 `\claimref{...}`。
6. 收口：列出当前能支持的判断、不能支持的判断、下一项决定性检查和停止条件。

## 5. 引用与版权

- 引用优先指向原始文档、源码、实验产物或官方说明。
- 本地文件引用保留路径和行号；PDF 引用保留页码；网页保留访问日期和版本。
- 只摘录建立论点所需的短句，以摘要和结构化转述为主。
- 不把付费、内部、受限或个人资料复制到外部服务。
- 引用格式服从用户或出版模板；没有指定时，新报告使用 `biblatex` + Biber，并在台账中保留更细的证据定位。

## 6. 交付自检

内容审查至少回答：

- 研究了什么，哪些来源真正读过？
- 哪些是来源明确说明、实际观察、推断、假设或证据不足？
- 量化结论的主体、样本、版本和复现状态是什么？
- 有哪些冲突、不可比项和读取缺口？
- 哪一项检查最可能改变当前判断？满足什么条件后停止？
